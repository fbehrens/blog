AeroSpace layouts · lesson 1

Where does a new window land?

After this lesson you can predict the new window's position before you press ⌘N.

Your screen is a tree

AeroSpace stores every window of a workspace in a tree.[guide]

  • Every window is a leaf. Every non-leaf node is a container.
  • Each workspace has exactly one root container.
  • Every container has a layout (tiles or accordion) and an orientation (horizontal or vertical). Together these give four names: h_tiles, v_tiles, h_accordion, v_accordion.[layouts]

This course writes trees compactly. h[1 v[2 3]] means an h_tiles root holding window 1, followed by a v_tiles container holding 2 and 3. Upper case (V[…]) means accordion.

The placement rule

Rule A new window is inserted into the same container as the most recently focused window, directly after it.

That's the whole rule. It's in the source, not in the guide: unbindAndGetBindingDataForNewTilingWindow in Sources/AppBundle/tree/MacWindow.swift binds the new window to mruWindow.parent at mruWindow.ownIndex + 1.[source] Three consequences follow:

  1. Focus first, then open. Focus picks both the container and the slot.
  2. A new window never creates a container. It only joins one that already exists. Nesting always comes from a command such as join-with or move, covered in the next lessons.
  3. Floating trap. If the last focused window is floating, there's no tiling parent to join, so the new window is appended to the end of the root container. Your config floats Finder, Chromium, and others, so watch for this.

The new window uses its container's orientation. In an h_… container it appears to the right of the focused window. In a v_… container it appears below. Normalization keeps the tree tidy: containers with one child are flattened, and nested containers alternate orientation.[normalization]

Play

Click a window to focus it, then press open new window. You can also click inside the box and use the keys n, hjkl, and x. Use join-with to build nesting, then watch where new windows go.

The simulator is a JavaScript port of AeroSpace's own tree code (assets/tree.js). It's checked against the before/after examples in the AeroSpace docs and tests. Window sizes are always equal here; resize isn't simulated.

Predict

Commit to an answer before you click. Wrong-then-right is how the rule sticks.

Dojo: do it for real

The dojo is a throwaway app whose windows are big numbered color blocks (assets/dojo/, bundle id local.aerospace.dojo). Press ⌘N to open a new window and ⌘W to close one. Running open again while it's running also opens a window.

~/c/teach/aerospace/assets/dojo/build.sh                     # once (already built)
open ~/c/teach/aerospace/assets/dojo/Dojo.app               # starts with window 1
  1. Switch to an empty workspace and start the dojo. Press ⌘N twice. You should see h[1 2 3], since each new window lands after the one you just focused.
  2. Focus 2 (alt-h/alt-l). Enter service mode with alt-shift-;, then press alt-shift-l (join-with right). You now have h[1 v[2 3]].
  3. Focus 1, say out loud where 4 will land, then press ⌘N.
  4. Focus 3, predict, then press ⌘N.
  5. Click a floating window such as Finder, then click back into a dojo window and press ⌘N. Next, activate Finder only, then run open …/Dojo.app from a terminal. Where does the new window land each time?

Recall

Close your eyes. State the placement rule and its three consequences, then reveal.

Same container as the most recently focused window, directly after it. (1) Focus first, then open. (2) New windows never create containers. (3) If the most recent window is floating, the new window goes to the end of the root container.
