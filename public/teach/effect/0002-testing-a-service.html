Lesson 02 · The payoff

Testing a service: swap the Layer, fake the disk

Why you split layer from defaultLayer in Lesson 1 — and how it makes skills.ts testable without touching a real filesystem.

In Lesson 1 you built two layers: Skills.layer (needs a FileSystem from outside) and Skills.defaultLayer (Bun's real FS baked in). That split looked like bookkeeping. Here's the cash-out: to test, you provide the open Skills.layer and hand it a fake filesystem instead of Bun's. Same service, no disk, deterministic.

The single win for today Write a test that runs Skills.scan against an in-memory filesystem and asserts the result — green in milliseconds, no real files. This is the move your msk/src/skills.test.ts already uses.

Two kinds of code, two test styles

opencode (and your msk) split testing along a clean line:

Pure functions → call directly

parseSkills in msk takes strings, returns data. No Effect, no layers — just expect(parseSkills(...)).toEqual(...). Keep pure logic pure so it's trivially testable.

Effects with deps → provide a fake Layer

scan needs FileSystem. You can't call it directly — you run it with a test filesystem provided. That's this lesson.

Step 1 — a fake filesystem

Effect ships FileSystem.layerNoop: a complete FileSystem where every method throws unless you override it. Override only the methods your code calls. scan uses two: 

import { Effect, FileSystem } from "effect"

const fakeFs = (children: string[], skillMds: string[]) =>
  FileSystem.layerNoop({
    readDirectory: () => Effect.succeed(children),
    exists: (path) => Effect.succeed(skillMds.includes(path)),
  })

Step 2 — provide layer, not defaultLayer

This is the whole idea. The open layer lets you inject the fake; the default layer would force the real disk.

const scan = (children: string[], skillMds: string[], root = "/root") =>
  Effect.runPromise(
    Effect.gen(function* () {
      const skills = yield* Skills.Service
      return yield* skills.scan(root)
    }).pipe(
      Effect.provide(Skills.layer),              // open: still needs FileSystem
      Effect.provide(fakeFs(children, skillMds)), // ...the fake satisfies it
    ),
  )
Why this works Skills.layer's type is Layer<Skills, never, FileSystem> — the FileSystem hole is visible in the type. Effect.provide(fakeFs) fills it. defaultLayer already filled it with Bun, so there'd be no hole to inject into.

Step 3 — assert

import { describe, expect, it } from "bun:test"

describe("Skills.scan", () => {
  it("returns only dirs that contain a SKILL.md", async () => {
    const entries = await scan(
      ["alpha", "beta", "gamma"],
      ["/root/alpha/SKILL.md", "/root/gamma/SKILL.md"],
    )
    expect(entries).toEqual([
      { name: "alpha", folder: "/root/alpha" },
      { name: "gamma", folder: "/root/gamma" },
    ])
  })
})
Run it — it's already in your playground This exact test lives in playground/skills.test.ts and passes: 
cd playground
bun test            # 2 pass, 0 fail, ~110ms — no real disk touched
Now add a third test yourself: when exists fails (return Effect.fail(...) from the fake), scan should still succeed and skip that entry — because the code uses Effect.orElseSucceed(() => false). Prove the error-handling works.
