Lesson 06 · The workhorse syntax

Effect.gen

You already write it in your sleep. This lesson is the layer under the habit: what yield* actually does, where the three type channels come from, how failure short-circuits, and the two gotchas (the missing *, the native throw). Knowing the mechanism is what lets you debug it when the types go sideways.

The single win for today Explain Effect.gen as do-notation built on JS generators: yield* = "run this effect, bind its success"; the return is your A; and E + R are the union of every effect you yielded. Then spot why a missing * is a bug the LSP catches.

The shape, and the one true mental model

Effect.gen takes a generator function and returns an Effect. The signature tells the whole story: 

// effect/Effect.d.ts (simplified)
const gen: <Eff extends Effect<any, any, any>, AEff>(
  f: () => Generator<Eff, AEff, never>,
) => Effect<AEff, /* E of every Eff */, /* R of every Eff */>

Read it as: the things you yield* are Eff (effects); the thing you return is AEff (the success). It is async/await for effects:

async / await

async function f() {
  const a = await getA()
  const b = await getB(a)
  return a + b
}

Effect.gen

Effect.gen(function* () {
  const a = yield* getA
  const b = yield* getB(a)
  return a + b
})

Same straight-line code. The difference is what it desugars to and what it tracks.

What yield* actually does

Every Effect is iterable — it implements [Symbol.iterator]. yield* (yield-delegate) hands control to that iterator, the runtime runs the effect, and the success value is handed back as the result of the yield* expression. Under the hood it's just flatMap stitched together for you: 

// what the generator compiles down to, conceptually
getA.pipe(Effect.flatMap((a) =>
  getB(a).pipe(Effect.flatMap((b) =>
    Effect.succeed(a + b)))))

That's why gen isn't magic and isn't slower-in-spirit than pipes: it is the pipe, written as statements. Use whichever reads better; mix them freely.

v4 note — no adapter Effect 3 tutorials sometimes show Effect.gen(function* ($) { yield* $(effect) }) or a _ parameter. Effect 4 dropped the adapter — you yield* the effect directly, as above. If you see $(...) in a snippet, it's old; delete the wrapper.

Where the three channels come from

This is the part worth burning in, because it explains 90% of "why is my type R = Foo | Bar?":

ChannelComes from
A — successthe generator's return value (or void if none)
E — errorthe union of the E of every effect you yield*
R — requirementsthe union of the R of every effect you yield*
Effect.gen(function* () {
  const cfg = yield* Config.Service          // R += Config
  const root = yield* cfg.skillsRoot          // E += never
  const files = yield* fs.readDirectory(root) // E += PlatformError, R += FileSystem
  return files.length                        // A = number
})
// ⇒ Effect<number, PlatformError, Config | FileSystem>

You never annotate these — they're inferred by accumulation. Add a yield* that needs Path and Path appears in R automatically. That's the Lesson-3 rule in action, one line at a time.

Failure short-circuits — like await throwing

If a yield*'d effect fails, the generator stops there. No later line runs; the failure becomes the gen's failure. You don't check return codes between steps: 

Effect.gen(function* () {
  const root = yield* cfg.skillsRoot          // if this fails…
  const files = yield* fs.readDirectory(root) // …this never runs
  return files
})

Recover with the usual combinators around the yielded effect or the whole gen: Effect.catchTag, Effect.orElse, Effect.option, Effect.either. Normal if / for / while / try all work inside the body — it's just JavaScript.

The two gotchas

1 · The missing *

const root = yield cfg.skillsRoot   // ✗
const root = yield* cfg.skillsRoot  // ✓
Plain yield hands back the effect object, not its value — root is now an unrun Effect. The Effect LSP flags this (floatingEffect / type mismatch). If a value "is an Effect when you expected a string," look for the dropped *.

2 · Native throw

// inside gen:
if (!ok) throw new Error("x")  // ⇒ DEFECT
if (!ok) return yield* Effect.fail(e) // ✓ typed E
A thrown error becomes an unchecked defect (it's not in E, won't be caught by catchTag). Put failures in the error channel with Effect.fail so they're typed and recoverable.

The traced sibling: Effect.fn("name")

When the gen is a reusable function — especially one you want on your trace — reach for Effect.fn. Same generator body, but it takes args and the name becomes a span: 

export const scanSkills = Effect.fn("scanSkills")(function* (root: string) {
  const fs = yield* FileSystem.FileSystem
  return yield* fs.readDirectory(root)
})
// scanSkills("/x") : Effect<string[], PlatformError, FileSystem>  — and emits a "scanSkills" span

This is the on-ramp to the telemetry lesson: msk already wraps its logic in Effect.fn("…"), so those functions are already spans. Point a tracer at them and the call tree shows up in motel for free. Effect.gen = anonymous inline block; Effect.fn("name") = named, reusable, traced.

Prove the mechanism 
# a gen IS a flatMap chain — these two print the same thing:
bun run -e 'import {Effect} from "effect"; Effect.runPromise(Effect.gen(function*(){const a=yield* Effect.succeed(2); const b=yield* Effect.succeed(3); return a+b}).pipe(Effect.tap(Effect.log)))'
Now drop the * from one yield and run bun run check in packages/skillman — the type of that binding flips to Effect<…> and arithmetic on it fails to compile. That red squiggle is the whole lesson in one keystroke.
