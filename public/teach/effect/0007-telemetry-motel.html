Lesson 07 · the OTEL payoff

Telemetry to motel

You already wrote the spans. Every Effect.fn("Skills.link") and Effect.withSpan("Project.root") in skillman is a span — they just had nowhere to go. This lesson adds the one piece that ships them: a tracer layer pointed at a local motel daemon. No code change to the domain, no per-function wiring.

The single win for today A trace exporter is just another layer. Merge one Otlp.layer into your AppLayer and the span tree you'd already named lights up in motel — built in main.ts only, so tests stay tracer-free.

What is motel?

motel (by Kit Langton, same author as opencode) is a local OpenTelemetry ingest server + terminal viewer, backed by SQLite. You point your app's OTLP/HTTP exporter at http://127.0.0.1:27686 and debug with real runtime evidence — from a TUI, a web UI, or an AI agent. No Docker, no cloud account, one daemon shared across all your local projects. 

# start the headless ingest daemon (forks, returns immediately)
bunx @kitlangton/motel daemon

# or the interactive TUI (ingest + viewer in one)
bunx @kitlangton/motel

# it listens here and appends the OTLP paths itself:
#   http://127.0.0.1:27686/v1/traces
#   http://127.0.0.1:27686/v1/logs

The tracer layer (your real code)

The combined OTLP layer lives in effect/unstable/observability. It needs two things provided underneath: an HttpClient to POST with (Bun has fetch, so FetchHttpClient.layer works), and a serialization format (OtlpSerialization.layerJson). Give it those and its output collapses to Layer<never> — a pure side-effect layer that installs the tracer into the runtime. 

// packages/skillman/src/telemetry.ts
import { Layer } from "effect"
import { FetchHttpClient } from "effect/unstable/http"
import { Otlp, OtlpSerialization } from "effect/unstable/observability"

// motel's local OTLP ingest. It appends /v1/traces, /v1/logs itself.
const MOTEL_URL = "http://127.0.0.1:27686"

// If motel isn't running the batched POSTs just fail quietly — the CLI still works.
export const layer: Layer.Layer<never> = Otlp.layer({
  baseUrl: MOTEL_URL,
  resource: { serviceName: "skillman" },
}).pipe(Layer.provide([FetchHttpClient.layer, OtlpSerialization.layerJson]))

Wire it in main.ts — and only there

The tracer belongs to the runtime, not the domain. Merge it into the AppLayer at the entry point. Your tests provide Skills.layer over fakes and never see it — telemetry is a production concern, kept out of the unit suite. 

// packages/skillman/src/main.ts
const AppLayer = Layer.mergeAll(Skills.defaultLayer, BunServices.layer, Telemetry.layer)

command.pipe(Command.run({ version: "0.1.0" }), Effect.provide(AppLayer), BunRuntime.runMain)
Why this is the whole job Otlp.layer sets the runtime's Tracer (a default service, Lesson 4). Once it's installed, every span that was already created by Effect.fn(name) / Effect.withSpan(name) gets collected and batch-exported. The names you wrote months ago for readability become your trace tree. That's the payoff the through-line promised: the spans were free because the named effects were already there.

Run it

Emit a trace 
bunx @kitlangton/motel daemon              # start ingest

# a moment later, motel knows your service:
curl -s 127.0.0.1:27686/api/services       # {"data":["skillman"]}

The gotcha that telemetry itself taught us

First run, the traces came back fragmented: Skills.sourceOf, Skills.linked and Project.root each showed up as a separate root trace instead of one tree under link. The cause was visible only because we were looking at telemetry: 

// BEFORE — install was an UNNAMED Effect.fn, so link/copy weren't spans.
// Their children had no parent span → each floated up as its own root.
const install = (write) => Effect.fn(function* (name) { /* ... */ })

// AFTER — name the span, and add a per-command root span in the CLI handler.
const install = (span, write) => Effect.fn(span)(function* (name) { /* ... */ })
const link = install("Skills.link", (from, to) => fs.symlink(from, to))

// cli.ts — wrap each handler so one invocation = one trace
report(Effect.gen(function* () { /* ... */ })).pipe(Effect.withSpan("cli.link"))
The rule Spans nest only under an active parent span. An Effect.fn with no name string is not a span — it runs, but it opens no span context, so anything it calls becomes a root. Name the boundaries you want to see, and give each top-level operation (here, a CLI command) a wrapping withSpan so its work collects under one tree.
