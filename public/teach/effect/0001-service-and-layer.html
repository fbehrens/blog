Lesson 01 · The keystone

From flat functions to a Service + Layer

Why every opencode module is a Context.Service with a Layer — and how to turn your skills.ts into one.

Your msk already writes good Effect 4. But it's flat: scanSkills, findSkillsDirs and friends are loose exported functions. opencode never does this. Every domain — Skill, Discovery, Config, Storage — is packaged as a Service (an interface you depend on) plus a Layer (the recipe that builds it). This one move is the difference in "shape." Get it, and the rest of opencode reads easily.

The single win for today Wrap your skills logic in a Skills service with a layer and a defaultLayer, exported as a namespace. One module, converted. That's it.

The three pieces

An opencode module is always these three things, in order (Effect docs: Services):

  1. Interface — what the service offers. Plain TypeScript.
  2. Service tag — an identity Effect can look up: Context.Service.
  3. Layer — how to build the implementation, declaring its own dependencies in its type.

What you have now

Straight from msk/src/skills.ts — dependency-on-the-call-site, no boundary:

// flat: a bare function. Its deps (FileSystem) leak into every caller's type.
export const scanSkills = Effect.fn("scanSkills")(function* (rootDir: string) {
  // ...uses FileSystem directly...
  return { entries, skillsDirs }
})

The same thing, opencode-shaped

Compare opencode/src/skill/discovery.ts. The pattern, applied to your skills module: 

// src/skills.ts
import { Context, Effect, Layer, FileSystem } from "effect"

// 1. INTERFACE — the surface other code depends on.
export interface Interface {
  readonly scan: (rootDir: string) => Effect.Effect<ScanResult, DuplicateSkillsError>
}

// 2. SERVICE TAG — the lookup key + the type "I need Skills".
export class Skills extends Context.Service<Skills, Interface>()("msk/Skills") {}

// 3. LAYER — build it once; deps (FileSystem) live in the LAYER's type, not callers'.
export const layer: Layer.Layer<Skills, never, FileSystem.FileSystem> = Layer.effect(
  Skills,
  Effect.gen(function* () {
    const fs = yield* FileSystem.FileSystem        // acquire deps ONCE, here

    const scan = Effect.fn("Skills.scan")(function* (rootDir: string) {
      // ...your existing logic, using the captured `fs`...
      return { entries, skillsDirs }
    })

    return Skills.of({ scan })                      // the implementation
  }),
)

// defaultLayer = layer with its dependencies already satisfied → plug-and-play.
export const defaultLayer = layer.pipe(Layer.provide(BunFileSystem.layer))

And the caller stops carrying FileSystem in its type — it just asks for Skills:

const program = Effect.gen(function* () {
  const skills = yield* Skills            // requirement: Skills, not FileSystem
  return yield* skills.scan(rootDir)
})

Why this is the keystone

It unlocks the refactor

Once each module is a Service, you merge them with Layer.mergeAll into one AppLayer — exactly opencode's app-runtime.ts. That's lesson 2.

It unlocks telemetry

Your Effect.fn("Skills.scan") is already a span. Add a tracer Layer to the AppLayer and every call shows up in motel. That's lesson 3 — almost free, because of the shape.
