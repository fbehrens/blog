Lesson 04 · The runtime's standard library

Default services

Lesson 3 hammered the rule: yield* a service and it lands in the R slot — you must provide it or it won't compile. So why does Effect.sleep, Random.next, Effect.log, and your own Config.string("SKILLS_ROOT") all run with R = never? This lesson is the exception that proves the rule.

The single win for today Name the handful of default services, explain why they don't show up in R (they're Context.References with a built-in default), and override one — which is exactly how it.effect makes Clock and Random deterministic in your tests.

The puzzle

By Lesson 3's rule, this should not type-check — it uses the clock and the RNG, yet asks for nothing:

const program: Effect.Effect<number, never, never> = Effect.gen(function* () {
  yield* Effect.sleep("10 millis")        // uses Clock
  const n = yield* Random.nextInt          // uses Random
  yield* Effect.log("picked", n)           // uses the Logger / Console
  return n
})
//                                  ^^^^^ R = never — nothing to provide

Clock, Random and Console are real services living in the context Map — the same machinery as your skillman/Config. The difference is they ship with a default value the runtime installs for you.

The mechanism: Context.Reference

A normal service (Context.Service) has no value until a layer builds one — so yielding it adds a requirement to R. A Context.Reference is a service that carries its own defaultValue(). In the Effect 4 source that is literally one line: 

// effect/Context.d.ts
interface Reference<Shape> extends Service<never, Shape> {
  readonly defaultValue: () => Shape   // ← always answerable, so never required
}

Note the never in Service<never, Shape>: a Reference contributes nothing to the requirements channel. That's the whole trick. The standard services are all declared this way: 

// effect/Clock.d.ts, Random.d.ts, Console.d.ts, ConfigProvider.d.ts, Tracer.d.ts, Scheduler.d.ts
export declare const Clock:          Context.Reference<Clock>
export declare const Random:         Context.Reference<{ ... }>
export declare const Console:        Context.Reference<Console>
export declare const ConfigProvider: Context.Reference<ConfigProvider>   // ← Lesson 5 leans on this
export declare const Tracer:         Context.Reference<Tracer>          // ← the telemetry lesson leans on this
export declare const Scheduler:      Context.Reference<Scheduler>
The mental model A default service is a let with a default value at the top of every program. Always in scope (so never in R), but you can shadow it for a block. Context.Service = a parameter you must pass; Context.Reference = a parameter with a default already filled in.

Overriding one

Because it's just a service, you override a default with the ordinary tools — provideService for a ready value, or a layer:

// swap the ConfigProvider for a fixed map (no real env)
program.pipe(
  Effect.provideService(ConfigProvider.ConfigProvider, ConfigProvider.fromEnv({ env: { SKILLS_ROOT: "/tmp/s" } })),
)

// the R slot was already `never`; providing here SHADOWS the default, it doesn't satisfy a requirement

You don't have to do this by hand for the common case. @effect/vitest's it.effect wraps your test in a TestContext that swaps Clock for a TestClock and Random for a deterministic one — for free. That's why a time-based effect under it.effect doesn't actually sleep.

Prove it — in your playground 
// the puzzle program above compiles & runs with R = never:
bun run -e 'import {Effect,Random} from "effect"; Effect.runPromise(Effect.gen(function*(){yield* Effect.sleep("10 millis"); return yield* Random.nextInt}).pipe(Effect.tap((n)=>Effect.log(n)))) '
Then the reveal: a non-default service like your Config.Service does appear in R and won't compile until provided. Same context Map; the only difference is whether a defaultValue() exists.

Why this matters for skillman

Your Config service (next lesson) is built on top of the ConfigProvider default service. Config.string("SKILLS_ROOT") reads from whatever ConfigProvider is in scope — the real env in production, a fixed map in tests — and you never thread it through your code. The telemetry lesson does the same move with Tracer: swap the no-op default for an OTEL one and your existing Effect.fn spans start flowing to motel, with zero changes to call sites.
