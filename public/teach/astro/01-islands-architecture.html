Astro Islands Architecture

Session 1 · For SvelteKit developers

1. The Problem Islands Solve

In SvelteKit, every page ships a JavaScript bundle. Even a mostly-static marketing page hydrates the entire component tree in the browser. That JS is cheap when every component is interactive — but expensive when 90% of your page is just text and images.

SvelteKit (full hydration)

  • Full JS bundle sent for every page
  • Entire tree hydrated on load
  • Great for highly-interactive apps
  • Overkill for content-heavy pages

Astro (islands)

  • Zero JS by default
  • Only explicitly-marked components hydrate
  • Great for content-heavy sites with some interactivity
  • Granular control per component
Svelte analogy
Think of it like SvelteKit but where every component defaults to SSR-only and you must opt-in to client-side hydration one component at a time.

2. What Is an Island?

An island is an interactive UI component embedded in an otherwise static HTML page.[1] The term was coined by Etsy engineer Katie Sylor-Miller (2019) and formalized by Preact creator Jason Miller:

Definition
"Render HTML pages on the server, and inject placeholders around highly dynamic regions that can then be hydrated on the client into small self-contained widgets."
— Jason Miller, 2020

Astro has two kinds of islands:

┌────────────────────────────────────────────────────┐ │ PAGE (static HTML, zero JS) │ │ │ │ <nav> static</nav> │ │ │ │ ┌──────────────────────────────┐ │ │ │ 🏝 CLIENT ISLAND (Svelte) │ ← hydrated JS │ │ │ Counter.svelte client:load │ │ │ └──────────────────────────────┘ │ │ │ │ <main> 1000 words of content </main> │ │ │ │ ┌──────────────────────────────┐ │ │ │ 🗄 SERVER ISLAND │ ← server-render │ │ │ UserGreeting server:defer │ in parallel │ │ └──────────────────────────────┘ │ │ │ │ <footer> static </footer> │ └────────────────────────────────────────────────────┘

Islands load and hydrate independently — they don't block each other, and they don't block the static content around them.[1]

3. Client Directives — The Core API

You turn any framework component into a client island by adding a client:* directive.[2] Without one, the component renders as static HTML on the server and ships zero JS. 

---
import Counter from '../components/Counter.svelte';
---

<!-- Static — renders HTML only, no JS sent -->
<Counter initialCount={0} />

<!-- Island — hydrated immediately -->
<Counter initialCount={0} client:load />

<!-- Island — hydrated when browser is idle -->
<Counter initialCount={0} client:idle />

<!-- Island — hydrated only when scrolled into view -->
<Counter initialCount={0} client:visible />
Directive
When it hydrates
Use for
client:load
Immediately on page load
Critical UI — nav menus, modals above the fold
client:idle
After page load, when browser is idle (requestIdleCallback)
Non-critical interactive widgets
client:visible
When the component enters the viewport
Below-the-fold components, infinite scroll, lazy charts
client:media
When a CSS media query matches
Mobile-only interactive widgets
client:only
Client-only — skips server render entirely
Components that need browser APIs at render time (e.g. WebGL, localStorage)
Important
client:only requires you to pass the framework name: client:only="svelte". The component won't render at all on the server, so there's no static HTML fallback.

4. Server Islands — The Other Kind

A server island is different: it renders on the server (not the client) but does so after the initial static HTML is sent. This lets you serve fast static HTML immediately, then stream in personalized or dynamic server-rendered content.[4] 

---
import UserGreeting from '../components/UserGreeting.astro';
---

<!-- Page renders instantly. UserGreeting streams in separately. -->
<UserGreeting server:defer>
  <span slot="fallback">Loading...</span>
</UserGreeting>
Client island vs Server island:
  • Client island: static HTML on server → JS shipped → hydrated in browser
  • Server island: static HTML on server → server re-renders the island → streamed as HTML → no JS shipped

5. Using Svelte Components as Islands

This is one-time setup, then it works exactly like your existing Svelte knowledge.[3]

# 1. Add the integration
npx astro add svelte

That creates/updates three files:

// astro.config.mjs
import { defineConfig } from 'astro/config';
import svelte from '@astrojs/svelte';

export default defineConfig({
  integrations: [svelte()],
});
// svelte.config.js  (auto-created)
import { vitePreprocess } from '@astrojs/svelte';
export default { preprocess: vitePreprocess() };
// src/pages/index.astro
---
import Counter from '../components/Counter.svelte';
---
<html><body>
  <h1>Hello</h1>
  <Counter initialCount={5} client:load />
</body></html>
Props limitation
Props passed to hydrated islands must be serializable — objects, arrays, strings, numbers, dates. You cannot pass functions as props. This differs from SvelteKit where callbacks flow freely.
Svelte 5 note
The current @astrojs/svelte (v8+) targets Svelte 5. For Svelte 3/4, use @astrojs/svelte@5.

6. Try This

Exercise 1 — Scaffold and observe
  1. Run npm create astro@latest my-islands-demo (choose "empty" template)
  2. Run npx astro add svelte
  3. Create src/components/Counter.svelte with a simple let count = $state(0) + button
  4. Add it to src/pages/index.astro without any client:* directive first
  5. Open DevTools → Network → reload. Notice: zero Svelte JS in the bundle
  6. Now add client:load and reload. The Svelte runtime appears in Network
  7. Change to client:visible and observe it only hydrates when scrolled into view
Exercise 2 — Compare directive timing

Add three copies of your counter to a page — one with each of client:load, client:idle, client:visible. Open DevTools Performance tab and record the page load. You'll see them hydrate at different times. Which one is most appropriate for a "subscribe to newsletter" form above the fold?
